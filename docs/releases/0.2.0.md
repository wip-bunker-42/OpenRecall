# OpenRecall 0.2.0

This release adds a dedicated spelling deck, configurable question labels and
calendar-based daily completion statistics to the offline Arabic desktop app.

- Create one spelling deck per local library and bind an ordinary source deck.
  Unique eligible Latin-script words/terms are collected from existing and new
  questions, answers, notes and alternative forms. Unknown names are included;
  URLs, email addresses and pure numbers are excluded. The extraction policy is
  versioned and runs locally in Rust.
- Source edits, deletion and rebinding retain vocabulary and learning progress.
  Each word keeps its last matching source-form context, even when every live
  source is gone. Original contexts load on request and support pagination.
- Spelling review starts with the whole target word on the native textarea's
  first line, a blank line below, focus in the field and an unselected caret at
  its beginning. The field is freely editable. There is no correction,
  comparison, automatic grade, synthesized speech or saving of user attempts.
  Leaving a presentation discards the attempt; undo, resume and restart restore
  only the target plus newline. Same-card polling, blur and disclosure preserve
  the current field. The four grades are available immediately.
- Explicit word deletion records an exclusion. Allowing collection again uses
  the current source and starts fresh progress. Deleting the whole spelling deck
  clears its owned data while preserving ordinary sources.
- Optional per-form `questionTitle` customizes the label-only H1. Missing/null or
  blank values use `السؤال`. Omitted variant titles inherit the root during JSON
  import; explicit null/blank resets that label. Titles remain plain text, up to
  160 Unicode characters without control characters or line breaks.
- Deck and library statistics count one completion per logical card/study day
  when its last effective review moves the due date to a later study day. Later
  reviews preserve earlier daily results; undo/deletion use surviving history.
  Library totals show the separate spelling-word subset. Current timezone and
  day-start settings, including Cairo DST, determine the calendar buckets.
- Rating buttons retain their Arabic labels and approximate intervals. The extra
  expected calendar date and delayed-rating caveat have been removed. Actual
  committed due-date feedback remains available after grading.
- Complete format-2 backups include spelling vocabulary, context snapshots,
  exclusions and every existing setting/progress/model/history collection. The
  versioned reader verifies genuine v0.1.0 format-1 payloads before upgrading
  defaults, including nested undo images. Restore still previews, exports a
  safety copy and replaces the library transactionally.

FSRS-7 and its 34-parameter model remain pinned to the existing upstream commit;
stability, stability_fast and difficulty are preserved. Scheduling, selection,
history, training, validation and transactions remain authoritative in Rust.
Schedule Penalties stay enabled by default.

See [automated evidence and limits](../testing/automated-results.md),
[the Arabic guide](../user-guide.ar.md), [human NVDA checks](../testing/human-nvda-checklist.md)
and [signing custody](signing.md). Automated tests cover real Windows WebView2
study, both backup formats, retained contexts, typed-attempt privacy and process
restart. No screen reader was launched. Build/signature results do not establish
an OS installer run or a complete v0.1.0-to-v0.2.0 installation/update test.

Windows 11 x64 is primary; Windows 10, Linux and macOS are secondary. Normal and
WebView2-inclusive offline Windows installers are signed for the updater. Linux
and both macOS architectures are built in CI; their runtime behavior has not been
tested here. Updater signatures do not provide a Windows publisher certificate
or Apple notarization. Linux retains the disclosed, unpatched
[upstream GLib iterator advisory](linux-glib-advisory.md); its alert remains open.
